# 课表分享格式 HITA2

`HITA2:` 口令由 Base64URL（无填充）的 GZIP UTF-8 JSON 组成。它接收统一的 `SharedTimetable` 快照；教务、ICS 和手工课程在本地展开为 `EventItem` 后都走同一编码器。`HITA1:` 口令仍可导入。好友数据继续保存为原有的 v1 规范化快照 JSON，内容摘要与旧版保持一致。

JSON 顶层字段如下：

| 字段 | 内容 |
| --- | --- |
| `v`、`id`、`n`、`m` | 版本 2、分享身份、昵称、`full` 或 `busy` |
| `t` | 课表名、学期名、学期起止毫秒、`Asia/Shanghai` |
| `p` | 每节课的开始与结束分钟数，按本地午夜计算 |
| `c`、`l` | 完整模式下的课程名表和地点表；忙闲模式没有这两个字段 |
| `g` | 与作息表精确匹配的课程，按课程、地点、星期、首末节分组，最后一个整数为周次位集合 |
| `x` | 未匹配节次但具有整分钟时间的课程：学期起始日的日期偏移与当天起止分钟 |
| `z` | 其余课程：精确的起止毫秒 |

`g` 的第 0 位表示学期起始日所在周的周一至周日，第 1 位表示下一周，依此类推；星期取 1（周一）至 7（周日），节次使用 `p` 的零基索引。完整模式的 `g` 行是 `[课程索引,地点索引,星期,首节索引,末节索引,周次位集合]`；`x` 和 `z` 的前两项也为课程与地点索引。忙闲模式省略这两个索引。重复发生的同一节课不会被周次位集合合并，额外记录会进入 `x` 或 `z`。

编码器只有在从节次反算出的起止毫秒与原始事件完全相等时才写入 `g`。不能精确匹配时写入 `x` 或 `z`，以保证包括调课、ICS 自定义时间和亚分钟时间在内的事件无损往返。解码后重新执行原有字段范围与课程数量校验，再映射回 `SharedTimetable`。二维码直接承载完整的 `HITA2:` 口令；超出 Q/M 级容量时不生成二维码，仍可使用口令分享。
