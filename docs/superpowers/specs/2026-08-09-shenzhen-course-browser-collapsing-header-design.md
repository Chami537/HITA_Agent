# 深圳课程浏览折叠头部设计

## 目标

让课程列表成为页面主体。用户向下浏览课程时，顶部浏览控制区随内容自然滚出屏幕，避免固定控件长期占据大部分可视高度。

## 范围

- 保留固定的页面标题栏与底部选课操作栏。
- 将来源切换、说明、学期与课程池筛选、搜索、智能推荐、选课预览和任务状态放入课程列表的滚动内容顶部。
- 控制区滚出屏幕后，在标题栏提供紧凑的筛选入口，用于快速回到列表顶部。
- 保持课程卡片、立即提交、定时提交、任务监控、取消和只读结果确认行为不变。
- 不修改教务请求参数、课程数量、并发数、时间范围或单次提交约束。

## 交互

1. 页面首次打开时完整显示浏览控制区和课程列表。
2. 用户向下滚动时，控制区与课程列表使用同一个滚动容器，控制区自然离开屏幕；标题栏保持固定。
3. 控制区不再可见且列表可继续滚动时，标题栏显示筛选按钮。
4. 点击筛选按钮平滑滚动回列表顶部。
5. 用户回到顶部后，筛选按钮隐藏。
6. 加载、登录失效、加载失败或空课程状态仍位于同一滚动容器中，不通过突然动画隐藏控制区。
7. 底部选课操作栏始终固定，并继续避让系统导航栏。

## 布局结构

- 外层继续使用纵向布局：固定标题栏、主体区域、可选的固定底部操作栏。
- 主体区域改为单个 `LazyColumn`。
- 控制区拆成若干 `item`，任务卡片和课程卡片继续使用稳定 key。
- 分页控制位于课程列表末尾。
- 通过 `LazyListState` 判断首个可见项，并驱动标题栏筛选入口及回顶操作。

## 状态与安全

- 复用现有 ViewModel 与 LiveData，不新增业务状态或持久化字段。
- 滚动位置仅属于界面状态，不参与任务创建或提交。
- 页面重组不得重复发起课程查询或选课请求。
- 任何真实提交仍必须经过现有确认对话框。

## 验证

- 添加纯策略测试，覆盖顶部、已折叠和不可滚动状态下筛选入口的可见性。
- 运行相关单元测试及完整 Debug 单测和构建。
- 在已连接手机上确认：向下滚动后课程信息占据主要区域；标题栏筛选入口可回顶；底部提交栏保持可用；未触发真实选课提交。
